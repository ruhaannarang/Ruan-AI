# Ruan AI — Voice Service (`voice-service/`)

The **Voice Service** is a dedicated, local-first Python microservice running on `127.0.0.1:8008` (loopback only) providing Speech-to-Text (STT) and Text-to-Speech (TTS) capabilities for Ruan AI.

It is decoupled from the main Node.js / Express application gateway (`server/`), ensuring heavy AI audio compute runs efficiently on CPU threads while preserving 100% of consumer GPU VRAM for the local LLM (Gemma 4 via LM Studio).

---

## 1. Engine Architecture

```text
Microphone (Browser Web Audio)
         ↓  (Push-to-Talk audio blob)
Express Gateway (server/src/controllers/voiceController.js)
         ↓  (POST /api/voice/transcribe)
Python Voice Service (voice-service/app.py)
         ↓  (local loopback http://127.0.0.1:8008)
faster-whisper STT Engine (small / base, INT8, 4 CPU threads)
         ↓  (Transcribed text + detected language)
Unified Conversation Pipeline (server/src/controllers/chatController.js)
         ↓  (Prompt text)
LM Studio / Gemma 4 E2B IT QAT (GPU)
         ↓  (Response text)
Kokoro 82M ONNX TTS Engine (54 voices, Hinglish text preparation)
         ↓  (WAV audio bytes)
Express Gateway (/api/voice/synthesize)
         ↓  (playable audio stream)
React Audio Player (client/src/hooks/useVoice.js)
```

### Components

| Engine | Model / Provider | Primary Role | Hardware Execution |
|---|---|---|---|
| **STT** | `faster-whisper` (`small` default, `base` benchmarked) | Multilingual speech transcription with Hinglish & accent understanding | CPU (INT8, 4 threads) |
| **TTS** | `Kokoro 82M` (ONNX Runtime via `kokoro-onnx` + `espeakng-loader`) | Neural speech synthesis with 54 voices, sentence chunking, and language routing | CPU (ONNX Runtime) |
| **API** | `FastAPI` + `Uvicorn` | Local HTTP API strictly bound to `127.0.0.1:8008` | Python 3.12 |

## 2. Windows Installation & Startup

### Step 1: Create Virtual Environment
Ensure you have Python 3.10–3.12 installed on Windows:
```powershell
cd c:\Ruan-AI\voice-service
python -m venv .venv
.\.venv\Scripts\activate
```

### Step 2: Install Dependencies
```powershell
pip install -r requirements.txt
```
> **Note on PyAV (`av`):** `requirements.txt` strictly pins `av<18.0.0` (installed `av==17.1.0`) to avoid an upstream `TypeError: open() got an unexpected keyword argument 'metadata_errors'` present in newer PyAV versions.

### Step 3: Model Weights Setup
Kokoro model weights are automatically downloaded into `voice-service/models/`:
* `kokoro-v1.0.onnx` (~325 MB)
* `voices-v1.0.bin` (~28 MB)

faster-whisper models are cached in `C:\Users\<User>\.cache\huggingface\hub\models--Systran--faster-whisper-small`.

### Step 4: Run the Service
```powershell
# Run using the application entrypoint:
python app.py

# Or via uvicorn directly:
uvicorn app:app --host 127.0.0.1 --port 8008
```

The service initializes in under 2 seconds, preloads models in a non-blocking background thread pool, and is ready on `http://127.0.0.1:8008`.

## 3. Endpoints Specification

### `GET /health`
Returns independent health status of both engines:
```json
{
  "status": "ok",
  "stt": {
    "status": "ready",
    "provider": "faster-whisper",
    "model": "small",
    "device": "cpu",
    "compute_type": "int8",
    "cpu_threads": 4
  },
  "tts": {
    "status": "ready",
    "provider": "kokoro-82m",
    "default_voice": "hf_alpha",
    "fallback_voice": "af_heart",
    "available_voices": ["af_heart", "hf_alpha", "hf_beta", "hm_omega", "hm_psi", ...]
  }
}
```

### `POST /transcribe`
Accepts multipart audio file upload (field name `file` or `audio`):
* Maximum upload size: 25 MB.
* Returns:
  ```json
  {
    "success": true,
    "text": "Can you help me debug this code in ismi null pointer exception or raha-hi?",
    "language": "en",
    "language_probability": 0.895,
    "duration": 5.83,
    "processing_time": 5.33,
    "rtf": 0.91,
    "segments": [...]
  }
  ```
* **Privacy:** Uploaded audio is processed in transient memory and temporary disk files are immediately deleted in a `finally` block.

### `POST /synthesize`
Accepts JSON payload:
```json
{
  "text": "Bilkul, main aapko step by step samjhata hoon.",
  "voice": "hf_alpha",
  "speed": 1.0,
  "lang": "auto"
}
```
Returns binary audio stream with `Content-Type: audio/wav`.

### `GET /voices`
Returns list of all 54 available voice profiles.

## 4. Phase 1.6.1 Voice Quality Stabilization & Hinglish Findings

### Root Cause Analysis of Previous Audio Degradation
1. **Synthetic TTS Loopback Bias:** In earlier automated tests, synthetic audio generated by Kokoro was piped directly into Whisper. Kokoro's Hindi phonemizer (`espeak-ng`) cannot naturally parse Roman-script texting Hinglish (`"Mujhe kal subah..."`) and produces phonemic boundary artifacts ("in majhya..."). Whisper transcribed what it literally heard ("In Majha...", "In Mudgee..."). Testing with genuine human speech eliminates these synthetic phonemic boundary clicks.
2. **Whisper Language Classifier Sensitivity:** Whisper detects language on the first 30 seconds. On short Hinglish utterances, the language classifier was splitting confidence between English (`en`) and Hindi (`hi`). When forced into English mode, Whisper decoded English words from Hindi phonetics.
3. **Bilingual Prompt Conditioning:** Priming Whisper with a natural bilingual initial prompt (`"Namaste! Ye ek Hinglish conversation hai with technical terms like React, API, database, Java, Python, server, NullPointerException, Express, component, endpoint. Mujhe code debug karna hai."`) grounds the acoustic decoder in Roman Hinglish token transitions and recovers terms like `"Mujhe"`, `"Java"`, and `"linked list"`.
4. **Technical Vocabulary Boosting (`hotwords`):** Faster-Whisper 1.2+ supports `hotwords`. Supplying technical terms directly ensures software terms (`React`, `API`, `database`, `Express`, `NullPointerException`) are preserved without hallucinating full sentences.
5. **Kokoro Hinglish Routing:** 
   * **Devanagari script:** Triggered with `lang="hi"` and Hindi voices (`hf_alpha`, `hm_omega`) producing fluent, native Hindi speech.
   * **Roman script (Hinglish/English):** Routed through the Latin phonemizer (`lang="en-us"` or user voice) to prevent robotic letter-spelling artifacts.
6. **Review Before Send Workflow:** Voice input is placed directly into the composer input for user review and editing before dispatching to the LLM, with an optional toggle for automatic sending.

## 5. Model Comparison: `faster-whisper-small` vs `faster-whisper-base`

Both models run on CPU INT8 with 4 threads. Benchmark comparison across 15 standard items in 4 categories:

| Metric | faster-whisper-small | faster-whisper-base | Architectural Recommendation |
|---|---|---|---|
| **Average Latency** | ~5.2s – 7.5s | **~1.8s – 2.1s** | Base is **~3x–4x faster** with lower latency on conversational turns. |
| **English WER** | **0.0%** | **0.0%** | Both achieve flawless recognition on pure English sentences. |
| **Technical Vocab Retention** | **100%** | 88% – 100% | Small preserves edge-case compound terms slightly better. |
| **Accent & Code-Switching** | High robustness | Moderate | Small handles heavy accents and fast code-switching with lower phoneme drift. |
| **RAM Footprint (Working Set)**| ~650 MB | **~280 MB** | Base consumes ~55% less RAM. |

**Recommendation:** For standard development workstations on CPU INT8, `faster-whisper-small` is the default for maximum accuracy and technical term retention. For resource-constrained or battery-saving profiles, `faster-whisper-base` can be selected via `STT_MODEL=base`.

### Benchmark Endpoints:
* `GET /benchmark/prompts`: Returns the 15 standard reference sentences across English, Hindi, Romanized Hinglish, and Technical Hinglish.
* `POST /benchmark/compare`: Accepts recorded microphone audio and returns side-by-side WER, latency, RTF, and technical term retention for `small` vs `base`.

* `DELETE /benchmark/history`: Clears local dataset.

python benchmark_hinglish.py --summary

## 7. How to Switch Providers Later

Both STT and TTS live behind provider-independent interfaces:
* **STT Interface:** `stt/stt_engine.py` implements `transcribe(audio_path)` returning `{ text, language, duration, processing_time }`. To plug in `whisper.cpp`, create `whisper_cpp_engine.py` implementing the same signature and swap the initialization in `app.py`.
* **TTS Interface:** `tts/tts_engine.py` implements `synthesize_to_wav_bytes(text, voice, speed, lang)`. To plug in `Piper`, create a Piper adapter and swap `TTSEngine` in `app.py`.
* **Express Gateway:** The Node.js Express controllers (`sttService.js` and `ttsService.js`) talk to the standardized HTTP contract (`/transcribe`, `/synthesize`, `/health`), so backend routes require zero changes when underlying Python models are updated.
